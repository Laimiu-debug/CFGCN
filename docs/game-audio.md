# 水墨配乐与游戏声音本地接入

2026-10-20。用户已授权三首配乐分别接主界面、探索、战斗，连同现有环境与音效先在本地试用，特别要求主界面循环自然。本轮新增 Runway 生成次数 / 积分均为 0；保留前轮三次实际生成原件，不新增角色配音。

## 素材与循环

运行清单为 `apps/website/art/audio/ink-v1/manifest.json`，编辑参数与接缝数据为 `loop-edit.json`，生成提示词与来源为 `source.json`。原件保留在 `.local/audio/runway-ink-v1/source/originals/`，原始音效源 / 分轨保留在 `.local/audio/ink-trial-v1/source/`。`python scripts/prepare-game-audio.py` 只处理上述已存在素材，不调用云服务；输出带 SHA-256 文件名的运行资源，重建不覆盖已接收的原件。

原曲包含明确的结束衰减，尤其主界面后半段不能直接整首循环。当前候选保留开头一次，按委托的名义节拍选取乐句周期，把上一轮尾音和下一轮开头用升余弦交叠。保留自然弹奏速度，不把名义 BPM 当作实测恒定节拍。运行件为 48 kHz、16-bit 立体声 PCM WAV，AudioBufferSource 在音频线程按采样循环，不依靠 JS 定时器或 MP3 播完后的重启。继承前轮固定增益，不逐轮自动调音量。波形接缝检查只能排除明显断点 / 插入空白，最终乐句、音色与长时间重复的听感仍需用户审听。

风、水、鸟使用原有 24 秒周期分轨，独立混音；水声按当前地图河道的同源曲线、实际位置衰减，干地区域不持续放流水。三首音乐、环境和 15 个单次音效合计约 26.04 MB；关闭声音时不请求音频，开启后才请求主界面曲与环境 / 音效，其他配乐随场景读取。带哈希资源复用浏览器 HTTP 缓存与单次会话解码缓存；本轮保留本地无损循环质量，不把音频包体当作地图 / WASM 预算。

## 行为接入

- 官网 / 游戏入口共用声音偏好，西游地图、五人演武与旧章回接到同一个 AudioContext，场景更换用 1.1 秒淡变。首次必须点击开启，避免浏览器自动播放限制；菜单、地图和演武均可控制，按钮具有三语名称、忙碌 / 按下状态与键盘焦点。
- UI 使用轻触、确认和返回音；地面 / 石坪脚步来自真实位移，停止、暂停、恢复存档或传送不伪造脚步。只播放主控脚步，避免五人步声堆积。
- 演武从真实施法释放事件区分经纹、棍风与水法；敌人实际掉血 / 被击退才触发命中，角色受伤、护盾受击、闪避与装备更换分别反馈。旧章回接入寒水 / 化身、本领成长、首领预警与胜负短声。演武没有奖励 / 结局的部分不伪造奖励或胜利。
- 暂停 / 整备冻结音乐、环境与单次音效的音频时间；后台同样暂停。继续时从原位置恢复。关闭时停止所有节点、取消请求、移除监听并关闭上下文。总单次音效最多 8 声，同类限频，胜负时短暂压低配乐。
- 游戏状态只接收同源且来自当前可见游戏 iframe 的消息；不改动地图、战斗、位置 / 章节存档，也不在 iframe 内创建第二份背景音乐。

## 验证与边界

自动检查：三首 PCM 的有效循环边界、实际文件哈希、采样跳变 / 无插入空白、模式选择、暂停、真实命中与空挥区分、实际位移 / 传送、河岸水声和结局单次触发。项目 `npm run check` 已通过：98 项 TypeScript / API 测试、76 项 Rust 测试及示例、共享美术 / 地形检查、类型、Clippy、WASM 与网站构建。

本地浏览器证据位于 `.local/qa/audio-integration-v1/`；主界面已实际持续播放并超过 6 次循环，单个音乐循环节点与三层环境保留，未报音频错误。探索 / 战斗 / 暂停 / 关闭的浏览器核查记录在本轮完成时补记。音乐听感与真实手机硬件分别验收，不将信号检查写作用户听感通过。本轮不提交、推送或部署，其他作品未实现的战斗不会因共用素材存在而被标成已接入。

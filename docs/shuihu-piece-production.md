## 总体范围与分批方式

- 人物底册第一版为 **108 将 + 60 名原著重要人物，共 168 人**。108 将的座次单独固定，额外人物不混入 108 的收集分母；晁盖尤其单列。168 是第一版明确名录，不声称穷尽 120 回全部有名人物，后续按原著逐回补遗，保留版本与新增原因。
- 当前交付顺序：总体规格 → 全名录与逐人完整提示词 → 三枚代表样板 → 同相机审阅 → 修形与材质 → 12 枚首批 → 分组完成 108 将和扩展人物 → 图鉴接入 → 战斗使用。只有三枚试制获本轮确认，后续批量生成按样板审阅结果继续。
- 资产中的人物身份、身体体态、服装、主兵器、持械姿态分别设计，不允许一个身体换 168 个头。职业道具用于表现军师、书吏、医师、工匠、店家与剧情人物，不能给所有人强配一件战斗兵器。
- 收藏人物不等于同时参战。建议战斗先验证 6 人小队、单场双方总计 18–24 枚，后续再决定 8–12 人队伍上限；不同时加载 168 份高清模型。水战、骑战、山寨经营、完整战役另立范围。
- 《水浒传》以 120 回本作为底册范围，座次核对第 71 回；人物关系和兵器须另外核对出场回目。影视、漫画、其他游戏的角色美术不作为可直接使用的资源。

## 造型与糖塑风格

目标是有手工糖塑温润感的精细案头收藏棋。琥珀质感与焦糖凹线结合鲜明衣甲设色，呼应共用纸绢 / 水墨 / 朱砂 / 古金 / 水青体系；面容、手掌、衣甲与兵器轮廓在棋盘上仍清楚。糖色是材质语言，不能把所有衣甲都变成单一蜂蜜色。

- 人体保留完整头、颈、胸、腰腹、胯、手、腿与足；约五头身，逐人制作稿范围 4.5–5，头 / 手 / 肩与兵器在棋盘上醒目。鲁智深更厚重、林冲相对清瘦但手肩有分量、扈三娘挺拔利落；保留年龄、脸型与个体体态，避免全员同身材。
- 面部与衣甲主体偏实，薄袖边、衣褶边和兵器装饰局部透光；避免全透明导致脸与胸腹相互穿见。眉眼、须发、刺青和衣纹以雕刻 / 浅浮雕与有节制的设色表达。
- 近看须有完整后脑、背衣、背带、衣摆、鞋底和兵器背面。禁止把正面贴图当作 360 度精细模型。纹样少而明确，保持宋代江湖文学语境；是原创游戏改编，不宣称历史复原。
- 不做棒棒糖插棍、融化糖浆、糖粒堆砌、儿童大头公仔、玻璃 / 宝石皮肤、镜面金属、荧光发光体。皮肤着色采用琥珀材质，不按绰号把人物变成兽头、鬼怪或非人的身体。
- 衣甲红、绿、蓝与金色形成明确主色 / 辅色 / 点色，逐人写出部位与配色；允许比首版鲜明，不做荧光或无材质区分的塑料。阵营提示仍用脚下环与界面图形，人物设色服务身份与造型。
- 棋子固定雕塑姿势，无需 A / T pose，无骨骼、蒙皮或战斗动作。位移、转向、轻微倾斜、命中、倒下可由整个根节点表达，不能据此称为完整身体动作。

## 尺寸、坐标与画面尺度建议

数字是虚拟桌游比例，单位为米；非实物打印承诺。**1 场景单位 = 1 米，人物约 1:28，标准人物 65 mm 高，底座直径 30 mm，格距 40 mm。** 不把 65 mm 误当真人身高，也不以相机自动适配掩盖角色高矮。

| 项目 | 建议值与约束 |
| --- | --- |
| 普通人物 | 不含座高 58–72 mm，魁梧 / 高大者最高 78 mm；每人独立标注目标值 |
| 底座 | 共用可编辑六角浅座，对边 30 mm、高 3 mm；由 Blender 制作，Tripo 提示词不生成底座 |
| 完整轮廓 | 含长兵器通常不高于 100 mm；主体足部与袍摆留在底座内，兵器可越界但不得遮住相邻格中心 |
| 长柄兵器 | 以人物高度 H 比例设计，常用 1.1–1.45H；特定原著长兵器可例外并单记，不能为塞进底座强行截短 |
| 单 / 双刀 | 单件约 0.45–0.65H；双刀分别保留握柄与刀刃，不与袖口融为一体 |
| 握柄 | 半径、双手间距、握点与刀口方向记录在每人源文件；细杆和绳索须留真实厚度 |
| 骑战变体 | 另建马匹与骑姿，不把步行人物简单放到马背；双格占地是否使用待战棋规则决定，本轮不生成马匹 |
| Blender | Z 向上、面向 -Y、足底原点；导出 glTF 后 Y 向上、面向 +Z；应用缩放 / 旋转并重导入核对 |
| 画面审阅 | 同地线、同相机、同灯光比较三人；棋盘俯视约 35–50 度，图鉴近看正面 / 两侧 / 背面 / 手与武器 |

建议林冲 69 mm、鲁智深 72 mm 且肩腹明显更宽、扈三娘 66 mm。轮廓差异需要在不看姓名时也能观察到。

## 模型层级、材质与资源预算建议

精细原件、图鉴高清件与战场件分别留存；网页只请求需要的一档。以下是待样板验证的目标，不是 Tripo 提示词能强制得到的结果，也不沿用西游怪海预算作为水浒验收。

| 档位 | 建议三角面 | 贴图与材质 | 使用方式 |
| --- | --- | --- | --- |
| Studio / Blender 母版 | 原件完整保留，清理后再统计 | 原始贴图和可编辑材质保留 | 不随网页全量下载 |
| 图鉴检视 | 人物含兵器 60k–120k | 主体 2K，面部必要时局部 4K；优先 2–3 材质 | 同时一枚，切换时释放上一枚 |
| 战场 LOD0 | 人物含兵器 8k–15k | 1K，优先 1–2 材质 | 近中景按阵容加载 |
| 战场 LOD1 | 3k–5k | 512–1K | 较远棋子，保持头像与兵器剪影 |
| 图鉴缩图 | 384 / 768 像素候选 | 从验收模型渲染，禁止用提示词海报冒充实物 | 108 格只加载缩图 |

糖感需在 Blender 与实际网页分别验证。Studio 的纹理生成不等于已经得到厚度、折射与透射参数；图鉴可试 glTF transmission / volume 与受控灯光，战场优先不透明 / 局部高光方案保持清晰。不能把 alpha 降低当成糖塑，也不能承诺所有浏览器原样支持导出材质。具体数值、包体与材质扩展清单在三枚实测后锁定。

## 兵器与配件

兵器底册与人物底册分离，共用类型可复用基础结构，名人兵器保留独特轮廓与装饰。每件有独立生成提示词、相对尺寸、握点、持械手、来源状态、可编辑源、三角面与哈希。长枪、朴刀、禅杖、双刀、钩镰枪、双鞭、双斧、狼牙棒、宣花斧、画戟、弓弩、盾、猎叉、水军短刀与职业道具均应覆盖。

首批三枚带兵器的雕像仅验证整体剪影，不能视为可独立活动的最终装备。正式资产要求人物与兵器保持独立刚性节点、完整手掌、握点与朝向，导入后逐件处理手 / 武器融合；不能承诺自动拆分能恢复所有遮挡细节。兵器节点可独立变换或更换，不需要骨骼；与身体焊成一体时只能随整体移动。若要手臂一起挥砍，还需要可活动的肩 / 肘 / 腕分件或骨骼与动作制作，完整静态人像不能直接产生自然挥砍。本轮仍以无骨骼收藏样板为范围，不把兵器独立节点等同于完整攻击动画。三枚以外的兵器先完成提示词，不自动扩成新增收费生成任务。

非战斗人物使用书卷、账册、扇、药箱、凿锤、针线、酒壶等身份物件。底册标为“原创造型建议 / 兵器未逐条考证”的项目，不写成原著唯一指定；进入该人物生成批次前补出场与兵器回目。常见绰号异文、姓名异体和版本差别另存别名。

## 聚义图鉴与模型检视设计建议

- 108 个固定位置按座次排列，36 天罡 / 72 地煞分组。支持姓名 / 绰号搜索、职业与兵器筛选、已聚义 / 已结识 / 未结识状态和 `已聚义 n / 108`。晁盖等扩展人物另页计数，不凑成 109 / 108。
- 状态区分“未结识、已结识、已聚义”和“模型待制作、制作中、可检视、载入失败”。开发中缺模型不冒充玩家没收集；浏览器打开过图鉴也不能自动算招募。
- 建议通过剧情、救援、任务与招募解锁，先不把收集做成付费随机抽取。108 全收集是长期内容目标，不是本轮三枚完成后即可达成的玩法。
- 详情页中央是模型，左右为人物短档案、兵器与出处；默认少字，可展开典故。简体 / 繁体 / 英文信息结构相同；未核对的英文绰号标记翻译待审，不给虚假典故。
- 检视以放大 / 缩小、平移观察中心和各部位近看为核心：脸、手、胸甲、背衣、鞋与兵器都能移到视口中央，近看时仍可调整角度；提供全身 / 面部 / 持械手 / 兵器定位及正面 / 两侧 / 背面 / 重置镜头。鼠标滚轮缩放，拖动改角度，平移有明确操作提示与按钮；触屏双指缩放 / 平移，单指改角度，键盘有等价控制。限制最近距离与俯仰防止穿模，不将观察中心锁死在胸口。显示 / 隐藏座与装备不应留下残缺手掌。模型检视尚未实现。
- 默认不自动旋转；减少动态时停转台与入场动效，切页 / 后台停止渲染。手动观察仍可用。灯光保持稳定，避免灯随模型转动把背面缺陷藏掉；相机限制距离与俯仰，避免穿模。
- 先加载当前选中缩图，再按需载高清 GLB；加载有进度 / 重试 / 取消与 WebGL 失败反馈。晚到的前一个请求不得覆盖当前人物；切页释放网格、纹理与渲染器。存储受限、损坏、版本升级和导入备份要保留原记录。
- 收藏状态、游戏招募状态与官网收藏分离；游客仅本地保存并明确显示，云同步和跨设备另行验收。模型检视暂不代表已实现招募 / 战棋 / 战役。

## UI 参考与系列一致性

《战场兄弟》的参考范围是角色 / 装备 / 属性的相邻组织、队列、背包、行动按钮、命中依据和清楚的悬停说明；参考官方开发日志，不复制其纹理、字体、图标、角色或版面像素。水浒使用现有纸绢、黛墨、水青、古金与朱砂，在梁山卷册、兵器架、聚义名册的语境中形成自己的界面。

- 战斗视口尽量露出棋盘，细血条、脚下选中轮廓、紧凑头像队列和图形技能；不新增常驻方块任务板。招募 / 图鉴 / 装备页可使用清楚分栏，不把西游透明 HUD 机械复制成满页漂浮文字。
- 所有按钮继续使用 `@cfgcn/ui` `Button`，颜色 / 字体 / 状态只从 `packages/ui/src/tokens.css` 取得。糖材质由现有 gold / gold-ink 等共用颜色派生，新增设计变量需先入唯一入口并同步。

- 六角格、行动点、疲劳、士气、援护与装备伤损可列后续战棋建议；具体规则、单局时长、永久死亡、山寨经营和骑水战都未在本轮确认或实现。不能照搬《战场兄弟》的数值系统即称水浒已设计完成。

## Tripo → Blender → 网页制作步骤与验收

1. 先保留本规格、人物底册、完整逐人 / 逐武器提示词和版本哈希。提示词不依赖 Tripo 认识人物名字，明确体态、面容、衣饰、兵器与站姿，单次长度按当前 Studio 输入框验证。
2. 使用现有 Studio 会员与可见报价，记录模型版本、生成模式、分件 / 纹理设置、任务 / 项目 ID、开始与结束状态、实际积分报价。不得将 API 余额与 Studio 混同，不充值或升级订阅。三枚生成按已确认范围执行。
3. 保存原始 GLB / 贴图与 SHA-256，保留原始结果；不覆盖已接收 Studio 资源。提示词、公开模型 ID 与本地原件路径可记录，凭据与临时签名下载链接不进入 Git / Notion / 报告。
4. Blender 逐枚检查人体完整、五官 / 手指、穿插、兵器直线与对称关系、背面和鞋底，统一真实毫米尺寸 / 轴向，整理刚性节点与底座，不绑骨。精细不等于只加面数；修形合格后再做 LOD 与贴图。
5. 在共用灯光下比较正、侧、背和俯视，同一地线看三人比例；再以棋盘缩放和图鉴近看各检查一次。拍模型转台与静帧，程序结构通过不替代造型认可。
6. GLB 重新导入核对尺寸、节点、无骨骼、材质 / 贴图、法线、包体和哈希。实际网页验证放大 / 缩小、平移、部位定位与正侧背观察，再检查切换、后台停止、窄屏、键盘 / 减少动态、加载失败与资源释放。
7. 用户审阅三枚通过后再锁定风格和预算、安排下一批。记录“生成完成、修形完成、材质完成、检视接入、人工审阅”的独立状态；不以 Studio 出图代替最终游戏资产。

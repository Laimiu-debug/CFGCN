## 画面取舍

2026-10-20 最新阶段调整：用户要求当前开发版暂不考虑加载速度，先丰富场景；旧首屏 1.5 MB 是历史目标，本阶段不据此压缩画稿或拒绝丰富内容。本轮保留较大 RGBA 村居 / 林木图集，不重复限网启动比较；来源哈希、资源正确加载与邻近图块释放保留。未来大量敌人的运行及实体手机验收仍需后续组合检查，不因开发阶段调整而宣称性能问题已解决。当前统一水墨 / 平面皮影方向及地图情况见 `art-direction.md` v2 与 `xiyou-exploration-map.md`，下文旧三维取舍按历史实现理解。

保留四款共用的三维东方绘本、工笔配色、青绿山水空间。体积、剪影、接地和危险范围优先；群怪的细碎装饰、独立骨骼、透明叠层和动态阴影不作为画质指标。主角与首领保留完整骨骼和施技动作，普通敌人采用同一 Tripo 原型的专用三维群体版本。地图的光照与接触层次预先烘焙，战斗中的关键反馈继续保持清楚。

2026-10-20 地图可信度 / 加载返工：地表起伏、窄路、碎石、草地与静态接地层共用附近地块和一张画稿，树石 / 地被复用已接收的 Tripo → Blender 模板，不给每株植物下载一个独特文件。地图踏勘改为先初始化当前样板角色与场景模板，切入旧战斗才加载其余角色、群怪和技能；河岸预取随实际战斗模式启动。地表 JPEG 也纳入持久缓存。场景原始字节预算 1.5 MB，通用 WASM 单独计量；当前引擎 gzip 仍约 6.1 MB，不能以模型复用宣称首开已经秒进。后续区域独特地标分包、实例同屏成本和怪海组合仍需实测。

这种分配遵循 [MDN WebGL 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)中减少绘制调用、共用纹理图集与控制显存预算的原则。通用技术原则与本项目实际请求 / 绘制证据分别记录，不把使用同一模型等同于所有硬件成本消失。

参考的具体取舍与本项目实现分开记录：

- [幻灵战队 Swarm 官方技术复盘](https://www.riotgames.com/en/news/the-tech-behind-swarm)介绍轻量敌人、共享导航、群体状态处理，以及地面粒子和阴影的成本。这里采用的原则是以真实怪海定位瓶颈、共享重复工作。我们目前的敌人运动与状态已经在 Rust 本地循环中处理，伙伴单独使用有预算的路径搜索；没有照搬 LoL 的服务器结构，也尚未实现敌人流场导航。
- [《Halls of Torment》开发者访谈](https://w4games.co/blog/w4-games-news-2/interview-with-chasing-carrots-developer-of-halls-of-torment-47)说明其九十年代预渲染视觉目标。由此得到的设计判断是：氛围与可读性可以来自美术和预计算，不需要每个对象都使用昂贵的实时材质。本项目继续使用可转向的真实三维群怪，未改为二维贴片。

## 已实施的普通敌人路径

`apps/xiyou/art/build_crowd.py` 从已接收的 Studio 狼妖与水妖运行文件制作 LOD，不调用收费 API，不覆盖原始模型。来源项目和哈希记录在 `crowd-metadata.json`，可编辑源为 `art/source/crowd_lods.blend`。

先焊接 GLB 导入时拆开的 UV / 法线接缝顶点，再用权重保护头脸、手脚和耳朵，最后减面。直接减面造成孔洞的旧候选已替换。不得为了达到面数而交付缺头、缺肢或破面的模型。

| 运行版本 | 实际三角面 | 上限 |
| -------- | ---------: | ---: |
| 狼妖近处 |        783 |  800 |
| 狼妖远处 |        583 |  600 |
| 水妖近处 |        784 |  800 |
| 水妖远处 |        404 |  420 |

四个网格合在一个 303,848 字节的 GLB，仍使用原型的两张 512 贴图。动作数据 PNG 为 278,155 字节，二者合计 582,003 字节。每个版本烘焙 1 个待机姿势、16 帧循环行走与 8 帧攻击起手。近处及攻击由 GPU 在相邻帧间插值；怪海远处的行走按 24 Hz 采样，根移动继续逐帧。攻击姿态跟随真实蓄力进度，不能因群怪优化删去起手；暂停保留当前行走姿势与时间。位置量化为 16 位、法线为八面体编码，最大位置误差小于 0.001 米；数据纹理明确按线性数据读取。

普通敌人不再每只创建骨架和动画播放器。同型号、同 LOD 共用网格、材质与动作数据，通过实例标记表达各自的动作相位、受击和定身。近处与攻击动作在相邻帧间插值，远处循环行走使用每秒 24 帧的采样姿势，根位置仍逐帧移动；待机 / 定身不重复读取同一帧。位置与法线共用一次纹理读取结果。材质参数合并为一个缓冲区，遵守 WebGL2 的绑定数量限制。

64 只以内使用近处版本；更多时保留距离主控最近的 32 只近处版本，其余使用远处版本。所有敌人继续参与伤害、拾取和 AI。显示简化不改变气血、经验和碰撞范围。回收实体复用，空闲池最多保留 64 个，避免长期积累。

接触阴影改为共享的两个三角面；不能为每只群怪铺数百三角面的地面网格。64 只以上时，细节阴影和精英头顶血条只保留最近 32 只，首领一直保留；不为远处每只敌人创建额外装饰实体。普通敌人的定身通过实例颜色和停止动作表达，首领保留独立的定身图形。真正有伤害语义的敌方预警和首领潮汐仍贴合地形，保留精确半径与暂停规则。主动技能使用有总量限制的立体莲瓣、棍风、水幕与连携，移动时保留腿部步态；隐藏骨架和零权重片段不持续求值，见 `xiyou-motion-and-fx.md`。

群怪地面高度来自启动时按同源地形生成的 0.125 米采样表，约占 1.75 MB 内存，无额外下载；15,000 处随机检查与精确地形的差异小于 2 厘米，表外回退精确计算。主角与技能范围继续使用精确地形。无变化的可见性和实例状态不重复标记更新。

群怪软避让使用可复用的空间桶，只查相邻九格，每格最多访问 24 个候选；不对所有敌人做两两距离比较。64 只以上的软避让决策按 20 Hz 更新并复用速度，位置仍逐模拟帧平滑推进，敌人身份变化立即重算；伤害、弹道和伙伴决策不降频。定身敌人和首领不被软避让推走，重合位置按确定方向分开。该避让避免视觉叠成一团，未引入每只敌人各跑一次 A*。

## 下载、本地运行与资源释放

Rust / WASM 的战斗逻辑和 WebGL2 绘制均在玩家设备执行，当前单人模式的服务器主要发送文件。换成 Rust 不会自动解决高面数、骨骼更新或透明覆盖成本。

引擎已有 IndexedDB 编译模块 / 字节缓存。本轮新增 iframe 范围内的 Cache API 资源缓存，覆盖运行清单中的模型、贴图、法术画稿和着色器。清单由 `scripts/xiyou-resources.mjs` 生成，包含完整 SHA-256 与字节数。相同内容跨会话复用，改版内容使用新键；读取时校验，损坏时重新下载，同一资源的并发请求共用一次下载。浏览器缓存不可用、超时或配额不足时回退到网络，不能阻止游戏启动。

首次可玩后两秒才顺序预取鹰愁涧的四个资源，不抢首屏带宽；启用节省流量时不预取。地区资源进出 GPU 仍遵循地图流式加载，磁盘缓存不会强迫旧地区一直留在显存。缓存只管理本游戏独立命名空间，按 48 MB 预算清理旧内容，不触碰本地存档或其他作品。

[MDN Cache 文档](https://developer.mozilla.org/en-US/docs/Web/API/Cache)说明该 API 可直接在页面中使用；缓存可能被浏览器回收。因此本地缓存是加速能力，不承诺永久驻留。已打开的游戏可使用已缓存的区域资源继续运行；整个门户的断网刷新与安装式离线启动尚未实现，首次打开及版本检查仍需要网络。门户字库不在 iframe 的资源缓存中，换区首次出现的新字库分片可能请求失败，断网时按共用字体栈使用系统后备字体；不能把这项资源验收写成整站完全离线。

## 压力验收

正常全局上限仍为 42，鹰愁涧普通敌人为 26，首领另计。压力场景不修改正式关卡数值。`crowd-benchmark` Cargo feature 才会编入 200 / 500 / 1000 敌人的入口，并只接受 localhost 的参数；正式构建不包含此模拟入口。

压力场景保留真实三人 AI、自动技能、连携、弹道与掉落；为了固定负载，持续补足敌人并防止死亡 / 升级中断。这是合成负载，不是已完成的后期关卡。总敌人数与实际可见数量分开理解，窄屏会剔除屏幕外对象。

每项先预热 8 秒，再测量 15 秒。记录 Bevy 实际更新帧间隔、P95 / P99、超过 33.34 ms 的比例、绘制调用和三角面，并确认模拟时间实际前进。不能把浏览器更高频率的 `requestAnimationFrame` 回调当作游戏 FPS，也不能把停止更新的空白画面当作性能通过。

标准比较为桌面 1280×800、200 / 500 / 1000 敌人，以及 390×844 触屏视口、DPR 2、4 倍 CPU 限速、500 敌人。记录实际 Canvas 分辨率；本机这些场景的 Canvas 分别为 1280×800 与 390×844。测试期间不并行运行 Blender、Cargo 或其他浏览器压力测试。

目标是桌面 500 敌人稳定接近 60 FPS，模拟低性能条件的 500 敌人不低于 30 FPS。1000 是额外压力探测。它们不等同于真实低端手机的 GPU、内存、驱动和长期发热表现；物理手机必须单独验收，不承诺所有设备绝不卡顿。

本轮最终测试数字、加载时间和缓存检查见进度页及 `.local/qa/crowd-*.json`、`resource-cache.json`。首次 / 再次加载、联网 / 已缓存资源断网、正常路线 / 怪海压力分别记录。未提交、推送或部署。

复测用 `scripts/bench-xiyou.mjs`，需要本地 Playwright 与 Edge。模块可安装在开发环境，或用 `CFGCN_BROWSER_RUNTIME` 指向已有的 `node_modules`；它不属于游戏运行依赖。PowerShell 中先设置 `$env:CFGCN_CROWD_BENCH='baseline'`，运行 `npm run build:xiyou` 保存修改前客户端与整套运行文件；修改后用 `optimized` 重建。依次运行 `npm run bench:xiyou -- baseline` 和 `npm run bench:xiyou -- optimized`，不要并行。两种文件均只写 `.local/crowd-bench/`，报告和同镜头截图写 `.local/qa/`。最后清除该环境变量，再进行正式构建，避免把实验客户端当成正常游戏。

## 正式玩法的新方向

2026-10-19 用户提出按原著章节逐步组成取经队伍：唐僧独行起步，五行山解救悟空，继而在鹰愁涧、高老庄和流沙河加入小白龙、八戒、悟净。全队共享经验，升级先选培养角色，再选该角色的技能；章节推进应改变敌人行为、地形和首领机制。角色技能需要配套动作，具体招式的游戏化改编与原著能力分别记录。

建议先做“唐僧短关 → 救出悟空 → 双人自动战斗 → 共享经验分配 → 保存章节”这一可玩闭环。用户已确认单人操控整队、伙伴自动跟随与战斗；跨地区的等级继承、倒地和救援规则尚未确定。用户随后要求先固化全项目美术，统一执行 [四大名著统一美术标准](art-direction.md)，覆盖人物、地图、动作、网页和所有按钮。大地图拟使用章节分区和路段加载，五人、召唤物与敌潮的资源预算需要重新实测。本文件后面的「山门试炼」仍指已有技术样板，不代表上述章节与五人队伍已完成。完整方案和实现状态同步在仓库 AGENTS.md 所列的 Notion 设计页、进度页与既有开发任务中。

新方向提出前，本地已开发八类修习、自动投射与环绕攻击、阶段敌潮、灵光吸取和战斗反馈。这些通用模块将用于新队伍系统；8 项规则测试、WASM Clippy 和四组种子模拟通过。实际生产预览用普通输入完成 163.45 秒、347 退敌、17 级的一局，经历 16 次升级选择并保存胜利行记；三语、320/390 控件、暂停、重开及减少动态检查通过。1,521 组桌面采样中位约 144 FPS，帧间隔 p95 中位 7.4 ms、最差 14 ms，敌群峰值 25、双分身同时在场时峰值 19 敌人；未完成真实手机或 42 上限压力验收。最后的共用色板投射另行补验了主题一致性、法术反馈与暂停恢复。证据为 `.local/qa/series-art-ui.json`、`series-xiyou.json`、`series-palette.json`；通用法宝实验不直接等同正式角色技能组。

## 如何运行

```powershell
npm ci
npm run build:xiyou
npm run dev
```

打开 `http://127.0.0.1:5173/#/world/xiyou`。WASD / 方向键移动，自动挥棍，空格施展定身法，E 召出分身；移动端可用方向按钮和法术按钮。保护悟空与师父，拾取灵光后从三门本领中选择其一，击败巡山妖王并完成护送。暂停、升级与结算使用可聚焦的原生对话框。一次完整成功护送约三分钟；「山门试炼」是原创试炼名称，没有冒充原著具体回目。

游客完成的结果保存在当前浏览器的西游独立版本化存档中，可从「西行记」查看和导出。不提供跨设备同步或中途续局；收藏仍仅表示世界书签。

Rust 版本由根 `rust-toolchain.toml` 固定为 1.97.1，Bevy 固定 0.20.0，依赖由 `Cargo.lock` 锁定。Windows 包装脚本会在当前进程内加载已有 Visual Studio C++ 工具，不修改机器默认 Rust 或全局 PATH。`wasm-bindgen-cli` 版本必须与锁文件一致；构建脚本优先查找 `.local/rust-tools` 或 `CFGCN_WASM_BINDGEN`，缺少时通过 Cargo 安装到项目本地目录。

## 代码边界与构建

- `packages/game-core`：独立 Rust 战斗、怪物、法术、护送、升级和结算，不依赖浏览器与渲染引擎。
- `apps/xiyou/rust`：Bevy 3D、glTF 骨骼动画、镜头、输入与网页桥接。当前使用 WebGL2 基线，没有提供 WebGPU 增强包。
- `apps/xiyou/src`：React 三语菜单、HUD、原生对话框、触控与本地行记。
- `apps/website/public/games/xiyou`：独立 iframe 启动页、分阶段加载、错误反馈与原始 GLB。跨窗口消息同时校验 origin 与 source；离开路由会卸载 iframe。
- 构建包由内容哈希命名，启动时读取不缓存的版本清单，再加载配套 JS / WASM，避免混用版本。Rust 首次编译比较久；修改后需要重新执行 `npm run build:xiyou`。

当前 WASM 30,646,341 字节，构建同时输出 7,480,696 字节的 gzip 包。加载器在支持流式解压 API 时下载压缩包，检查实际内容以兼容服务器已解压的响应；压缩文件缺失、损坏或浏览器缺少 API 时回退到原始 WASM。独立生产预览已验证正常压缩路径及三种回退。压缩减小传输量，仍需下载、解压、编译和资源初始化；当前没有生产部署，发布前还需配置缓存与原子切换，并验证普通网络和目标设备。

程序生成器保留师父、狼妖和山道流程资产；悟空已替换为 Studio 生成并经 Blender 修整的模型。人物均有 Idle / Walk / Strike，悟空 32 根骨骼，师父和狼妖各 13 根。山道包含石径、松树、亭与石灯。检查脚本核对 GLB 结构、有限顶点、动画顺序、权重归一、骨骼数、源文件与体积，并强制检查人物的面数、贴图、骨骼和绘制单元预算；CI 已接入该检查。

下载后的模型先运行只读源文件的导入检查：


检查器支持 GLB / glTF、FBX 和 OBJ，保留原文件哈希，输出源坐标、网格面数、UV、贴图尺寸、骨骼与动作报告，以及四向视图。仅检查副本做身高与脚底归零；骨骼显示形状不计入模型尺寸。本轮先用旧占位资产试跑，再检查了真实 Studio 输出。通用视图按文件原轴向命名，正式模型另做朝向与身体中心修正。

后续资产沿用以下流程：

1. 准备独立人物建模参考，手脚与尾巴清晰分离、A 姿、无地面和 UI；武器单独制作，避免与手臂融合。
   场景按亭、石灯、松树和山石等独立组件制作、修整与拼装；地形、道路和通行范围在 Blender / 引擎内安排，不把整张关卡参考图直接当成可用地图网格。
2. 核对可用模型、参考、参数和费用，再提交一次生成；提交结果未知时先查任务和历史，防止重复消费。
3. Blender 检查实际网格、拓扑、比例、朝向、贴图授权与材质；减少冗余面和材质，修正手、脸、衣摆和尾巴。
4. 绑骨与权重、走跑和棍击动作另行完成；静态模型生成不自动交付可用骨骼动画。保存原始结果与可编辑源文件。
5. 导出 GLB，核对动画、材质、资源预算与真实镜头；通过验收再替换首轮模型。不得把生成参考图或任务返回成功写成资产验收。

### 本轮悟空与性能验收

独立生产预览 `http://127.0.0.1:4173/#/world/xiyou` 已实际请求新版 GLB，响应哈希与运行文件一致，确认完成角色替换。真实移动、自动攻击、定身、分身、暂停恢复、自然失败与重开通过；390 / 320 CSS 像素无横向溢出，减少动态设置可传入游戏，应用异常与警告记录为空。本轮约 34.6 秒自然失败，退敌 12，另与之前完整规则模拟分别记录。

性能使用 Rust 引擎最近 120 帧的真实时间间隔，随状态每约 0.1 秒汇总，不把截图次数或无效的浏览器帧回调当作 FPS。测试机 RTX 4070 Ti SUPER、独立 Edge / WebGL2：桌面采样 293 组，敌人峰值 19 只；双分身同屏时实际测到 14 只敌人加 2 个分身，不能把两个独立峰值当成 19 加 2。桌面帧率中位约 144 FPS，帧间隔 p95 的中位约 7.3 ms、最差约 7.4 ms。窄视口采样 27 组同约 144 FPS，只代表此桌面 GPU 的窄视口。

完整新进程的本机冷启动约 17.5 秒，仍含 WASM 编译、图形初始化与资源处理，不能据压缩比例宣称同幅度的启动加速。压缩下载以及 gzip 缺失、解压 API 缺失、压缩数据损坏后的原始包回退全部通过；后三项复用浏览器进程的启动时长不作为冷启动数据。普通公网、真实手机、低端 GPU、完整 42 只敌人的上限场景与长时间散热仍待验收。

## 资源与接入接口

每人提供图像内嵌的 `*-actions.blend`、运行 `*-actions.glb`、16 个部件 PNG、运行图集、manifest 和关键帧图。八套依然各为 16 个骨骼、64 个顶点、32 个三角面和一个不受光的双面裁切材质。新动作不强制套旧的单文件 1.5 MB 门槛；当前开发阶段以画面与动作质量优先，包体仅如实记录。

`catalog.py` 是编排源，根 `manifest.json` 为可读运行目录；每招记录时长、蓄力结束、释放结束、事件时点、挂点、上身片段、双手握持和姿态关键点。`surface_sockets` 给出真实手心、握点和兵器远端的分件 / UV 标记；刚性皮影片可用该片三个顶点与同一骨骼变换求世界挂点，不要把前臂关节头当成手心。它不记录伤害 / 冷却，不能直接替代战斗规则。

- 站定：播放完整身体片段；角色有沉身、承重、前脚进步、兵器与肩腰发力、回到备势。
- 移动：腿和骨盆由 `WalkLower` 控制，上身由对应 `_Upper` 控制，二者使用独立时间；下身相位应由实际地图位移推进，禁止每次施法归零。浏览器检视按该导出步长演示，不等同于游戏已接入。
- 上身遮罩：abdomen、body、head、双上臂 / 前臂、weapon、accessory。下身遮罩：pelvis、双 thigh / shin / foot。GLB 实际通道已去掉越界骨骼，不能只依赖片段名字。
- 事件：在模拟时间跨过 manifest 的事件时刻时触发一次。暂停 / 培养必须同时冻结动作、步态、位移和事件；恢复时不能重发已经触发的事件。
- 后撤：骨骼保留原地动作，独立的 facing-x 曲线提供两步位移；碰撞系统批准位移后才能移动根节点。不能把检视页的演示位移直接写进战斗位置，或叠加两次位移。
- 左右：继续使用侧面与镜像；未新增正背面，也没有固定持械手的另一套反向画稿。

双手持械根据各自臂长求解，前后手接触同一杆身。WOOP 中后前臂为叶骨，其 Blender 显示尾点可能落在前臂中段；本轮改用画稿的 `distal` 手心点求臂长、握点与导出表面检查。出招时后臂从躯干后移至前层，杆身放到双手后面，避免实际手心仍被胸衣遮住或杆身直接盖住手掌；收势恢复原层级。四元数相邻键保持同一半球，避免 q / -q 插值突然翻转。静止承重通过真实图集 alpha 鞋底检查，不能用透明矩形边缘代替。
